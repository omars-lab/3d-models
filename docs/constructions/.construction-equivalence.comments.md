The table itself was fine. The cause was a code span in §4 that wrapped across a line break (`bikar render --piece Coaster --format stl` / `--check`). GitHub renders that, but Obsidian's editor pairs backticks line by line, so every backtick after it paired with the wrong partner and everything from §4 on — this table included — showed as raw text. Fixed by putting the span on one line. On hooks: there were none for this, now there are two, in the docs gate (runs on every commit): D6 fails a code span that runs onto the next line, and D7 fails a table row whose cell count doesn't match its header (a | inside backticks is the usual cause). Run over the whole tree they found 133 wrapped spans in 55 files and 13 real table defects in 6 tables — all fixed in PR #385 (commit 0212e38). Write-up: docs/issues/obsidian-wrapped-code-span.md.
