# Research survey: LEGO grid geometry, clone-plate variance, split-pattern prior art, and 0.2 mm seam visibility

*Research date: 2026-08-02. Prepared as Appendix-A source material for the lego-pattern-set design doc.*

Scope note: this survey feeds `docs/lego-pattern-set-design.md` (one Islamic-geometry pattern split on the 8.0 mm stud grid into a c×r array of printed pieces, footprint 8n−0.2 mm per piece, 0.2 mm designed seam) and calibration coupons LG-P1 (seam registration) and LG-P2 (clone-plate clutch). Every claim below is tagged with the URL it came from and whether the URL was actually fetched. Where a number appeared only in a search-result snippet and the underlying page could not be fetched, it is explicitly marked **snippet-only** and should not be treated as settled.

## 1. LEGO-brand baseplate dimensions (primary-source first)

### 1.1 LDraw part files (fetched verbatim, raw `.dat` via curl)

**`stud.dat` primitive** — fetched raw from https://library.ldraw.org/library/official/p/stud.dat. Full geometry lines:

```
1 16 0 0 0 6 0 0 0 1 0 0 0 6 4-4edge.dat
1 16 0 -4 0 6 0 0 0 1 0 0 0 6 4-4edge.dat
1 16 0 0 0 6 0 0 0 -4 0 0 0 6 4-4cyli.dat
1 16 0 -4 0 6 0 0 0 1 0 0 0 6 4-4disc.dat
```

The cylinder is scaled radius 6 LDU and −4 LDU in Y (LDraw Y is down, so the stud rises 4 LDU above the surface), capped by a disc at y = −4. So in LDraw: **stud diameter 12 LDU, stud height 4 LDU**. At 0.4 mm/LDU that is **4.8 mm diameter, 1.6 mm height**. Note below (§1.3) that measured secondary sources put the physical stud height at 1.7–1.8 mm; the LDraw 4 LDU value is a modeling convention, not a measurement.

**Part 3811, Baseplate 32×32** — fetched raw from https://library.ldraw.org/library/official/parts/3811.dat. Header: `0 Baseplate 32 x 32` / `0 Name: 3811.dat`, author James Jessiman. Body references subpart `s\3811s01.dat` plus sixteen `stug8.dat` 8×8 stud-group placements at X/Z ∈ {−240, −80, 80, 240} — i.e. group centers 160 LDU apart, which is 8 studs × 20 LDU. Outer edge geometry runs to ±320 LDU, so the plate is **640 × 640 LDU = 256 × 256 mm**, i.e. 32 modules × 20 LDU (8.0 mm) exactly. **Stud pitch in the primary model data: 20 LDU = 8.0 mm.**

**Subpart `s\3811s01.dat`** ("Baseplate 32 x 32 without Top Surface") — fetched raw from https://library.ldraw.org/library/official/parts/s/3811s01.dat. Side walls are `rect2p.dat` at y=2 scaled 2 in Y (spanning y=0 to y=4), bottom edge/corner primitives at y=4, corner cylinders at y=0 scaled 4 in Y. So the LDraw model gives the baseplate slab a thickness of **4 LDU = 1.6 mm**. Two corrections to received wisdom follow directly from the file: (a) the task brief's working assumption "a baseplate is 8 LDU thick" is **not** what the LDraw part says — 8 LDU (3.2 mm) is a normal *plate* height, and the baseplate is modeled at half that; (b) this agrees with the physical description in the Brickyard review (§2): "LEGO standard baseplates: half plate thick (1.6 mm), no anti-studs."

**Part 4186, Baseplate 48×48** — fetched raw from https://library.ldraw.org/library/official/parts/4186.dat. Header `0 Baseplate 48 x 48`; body places nine `stug-16x16.dat` groups at X/Z ∈ {−320, 0, 320}, i.e. 16-stud groups on 320 LDU centers — again 20 LDU pitch, total **960 × 960 LDU = 384 × 384 mm**.

**Part 628** — access failed: https://library.ldraw.org/library/official/parts/628.dat returned **HTTP 404** (verified twice, curl -I). The 48×48 plate exists in the official library as 4186; I could not confirm any official `628.dat`. Do not cite "628" as an LDraw part without checking the parts tracker by hand.

**LDU scale.** The LDraw file-format article at https://www.ldraw.org/article/218.html (fetched via WebFetch summarizer) states "1 LDU = 0.4 mm" with a table: brick width 20 LDU, brick height 24 LDU, plate height 8 LDU, stud diameter 12 LDU, stud height 4 LDU — and, per the same page, these conversions are approximations that should be verified against physical parts for critical work. (Caveat: this fetch went through a summarizing model, not raw text; the 0.4 mm/LDU convention is corroborated by every secondary source in this survey.)

### 1.2 Patent and official LEGO tolerance statements

**US 3,005,282 ("Toy building brick", 1961)** — fetched https://patents.google.com/patent/US3005282A/en. Finding: **the patent text contains no numeric dimensions in mm or inches.** It specifies geometric relationships only: tubes coaxial with the center of each four-stud square; the tube's circular cross-section touching the four stud cross-sections; secondary-projection height equal to cavity depth. So "4.8 mm is in the patent," which circulates in secondary sources (e.g. the Binder Clip Scorpion article below says "listed in patent: 4.8 mm"), is **not supported by the patent text as served by Google Patents** — treat 4.8 mm as an LDraw/industry nominal, not a patent citation.

**Official mould-accuracy claim, fetched wording.** The Rambling Brick (https://ramblingbrick.com/2018/01/28/celebrating-60-years-of-lego-bricks-endless-creativity/, fetched) reproduces a LEGO Australia press release: *"The moulds used to produce LEGO® elements are accurate to within 4my/0.004mm – less than the width of a single hair."* — attributed by that article to the official LEGO press release, in the context of clutch power. This is the best-provenanced version of the widely-cited tolerance claim I could actually retrieve.

**Conflicting figures in circulation, recorded rather than resolved:**
- **0.004 mm** ("4my") — LEGO AU press release, via fetched Rambling Brick article (above).
- **1/200 mm = 0.005 mm** — appears in Google's snippet of LEGO's own history article "Quality in every detail" (https://www.lego.com/en-us/history/articles/d-quality-in-every-detail). **Snippet-only:** direct fetches of that page failed (HTTP 504 then 503 on regional variants; a curl with browser UA returned a 564-byte block page). Access failed: https://www.lego.com/en-us/history/articles/d-quality-in-every-detail, https://www.lego.com/en-ca/history/articles/d-quality-in-every-detail, https://www.lego.com/en-us/aboutus/lego-group/how-we-make-lego-bricks (404).
- **0.01 mm / "10 micron"** and **0.002 mm** — circulate in engineering-blog secondary sources surfaced by search (e.g. thewave.engineer, bricksetpricetracker.com — not fetched); one search summary itself noted the 0.002 mm figure "lacks documented sources." None of these should be quoted as settled.

The honest statement for the design doc: *LEGO's own communications put mould accuracy in the 4–5 µm class (0.004 mm per a fetched press-release quote; 1/200 mm per an unfetchable lego.com page); larger figures (10 µm, and a viral 2 µm) are secondary and unattributed.* For our purposes every variant is ≥20× tighter than FDM (§4), so the disagreement does not change any design decision.

**Official baseplate sizes** — fetched https://www.lego.com/en-lt/service/help-topics/article/baseplates (LEGO customer service): "The gray baseplate is the largest, measuring 48 x 48 studs, or 15'' (38cm) x 15'' (38cm)." and "The others are 32 x 32 studs, or 10'' (25cm) x 10'' (25cm)." Consistent with the LDraw-derived 384 mm and 256 mm (LEGO's cm figures are rounded). The 10700-class plate (set 10700, Classic Green Baseplate) is a 32×32 in this family; I did not separately verify its part number against the current mould generation.

### 1.3 Stud height/diameter cross-check from independent secondary sources

- **Robert Cailliau's measurement pages** — fetched https://www.cailliau.org/Alphabetical/L/Lego/Dimensions/General%20Considerations/%20General%20Considerations-en.html. Measured/derived values: horizontal pitch **8.0 mm exactly** (derived by measuring extended distances across a baseplate — note this is itself evidence that LEGO pitch does not accumulate measurable error over a multi-stud span, §2.2); knob diameter **4.9 mm** ("measured & computed"); knob height **1.8 mm** (measured); plate thickness 3.2 mm (exact, 1/3 of 9.6); **play 0.1 mm per side**, i.e. a 2×4 brick is 31.8 × 15.8 mm against a 32 × 16 mm grid cell, leaving a **0.2 mm gap between adjacent bricks** — "my measurements have consistently turned up the value of 0.1mm play on each side." This is the direct empirical precedent for our 8n−0.2 mm piece footprint: LEGO itself leaves the same 0.2 mm inter-part gap.
- **Brick Owl stud-dimensions guide** — fetched https://www.brickowl.com/help/stud-dimensions. Pitch 8 mm with brick length "8x − 0.2 mm"; stud height **1.7 mm**; plate height 3.2 mm; "0.2 mm ... tolerance on either side of the brick" (their wording; the 8x−0.2 figure implies 0.1 mm per side, matching Cailliau).
- **Binder Clip Scorpion caliper article** — fetched https://binderclipscorpion.com/2023/02/08/should-plates-between-studs-be-an-illegal-lego-building-technique/. Digital-caliper measurements: stud diameter **"roughly 4.88 mm"** (vs the 4.8 mm nominal, which the author mis-attributes to the patent); stud-to-stud clear gap **3.12 mm** (12.88 mm outer over two studs, cross-checked by direct measurement); plate thickness measured **≈3.17 mm** (±0.01), tiles ≈3.162 mm.
- Access failed for two further planned cross-checks: https://brickarchitect.com/dimensions/ (404 — the page has evidently moved; not found under a verifiable URL) and https://www.brightontoymuseum.co.uk/index/Lego_dimensions (403).

**Recorded disagreements (do not silently pick a winner):** stud height **1.6 mm (LDraw model) vs 1.7 mm (Brick Owl) vs 1.8 mm (Cailliau, measured)**; stud diameter **4.8 mm (LDraw/nominal) vs 4.88 mm (caliper, one source) vs 4.9 mm (Cailliau, measured)**. For a printed *socket* that must clutch real studs, design against the measured 4.85–4.9 class, not the 4.8 nominal; a coupon (LG-P2) is the right way to settle it for a specific printer+material.

## 2. Clone/compatible baseplate variance

### 2.1 Named systems and what is actually documented

- **Mega (Mattel).** Of the sources surveyed here, none provides a caliper number for Mega stud pitch or diameter. The Brick Blogger (fetched, https://thebrickblogger.com/2016/06/a-lego-fans-encounters-with-mega-bloks/) reports qualitatively: "Because Mega Bloks is not a systemized construction toy like LEGO, their building elements are not always compatible" and "The rest of the parts feel cheap, and are very inconsistent in both color and clutch-power. Some are way too tight, others are too lose [sic]." A search summary (secondary, unfetched pages) describes Mega's four size classes, with only the "Micro" class nominally LEGO-scale. Net: Mega interop is anecdotally inconsistent; no pitch delta is documented in anything I could fetch.
- **Brickyard Building Blocks** (Amazon/Walmart-class brand) — fetched review at https://brickmodelrailroader.com/index.php/2022/06/10/review-brickyard-building-blocks-lego-compatible-baseplate/. Key quantitative/fit findings: Brickyard 32×32 plates are **full plate thickness (3.2 mm) with anti-studs**, vs "LEGO standard baseplates … half plate thick (1.6 mm)" with none; fit verdict "Both stud and anti stud connections fall pretty close to that sweet spot … Not too tight and not too loose"; dimensionally "a near perfect match to standard LEGO dimensions"; no observable warp when mated to genuine LEGO plates. This is a qualitative pass, with no numbers.
- **Strictly Briks / SCS Direct** — access failed: https://strictlybriks.com/product-category/shop-by/baseplates/ and https://strictlybriks.com/ both 404'd. An SCS Direct "guaranteed tight fit" marketing claim appeared **snippet-only** in search results. No measurements obtained.
- **Gobricks / Cobi / Mork / Qman class** — fetched https://latericius.com/en/blogs/blog/lego-compatible-building-blocks (enthusiast guide, secondary): clone brands use "the same LEGO® measurements"; Gobricks "virtually indistinguishable"; Mega "highly compatible"; and it states the unit brick footprint as **"7.8 x 7.8 mm"** height 9.6 mm — i.e. the 8.0 pitch minus 0.2 mm play again, corroborating §1.3. The guide provides **no per-brand mm measurements**.

### 2.2 Accumulated pitch error across a 32-stud span — explicit absence finding

A targeted search ("stud spacing/pitch accuracy across 32 stud baseplate accumulated error…") returned only marketing copy and generic tolerance talk; **no source surveyed here publishes pitch-consistency measurements across a multi-stud span for any clone plate.** Two adjacent facts bound the problem: (a) for genuine LEGO, Cailliau derived the 8.0 mm pitch *by* measuring long spans across a baseplate and got a value he was willing to call exact, so genuine-plate accumulated error is below enthusiast-caliper resolution; (b) for clones, the best available datum is the qualitative Brickyard "near perfect match" over 32 studs. For our design the load-bearing question is sharper than anything published: a c×r piece array bridges seams, so pitch error accumulated over each piece's n studs lands entirely in the seam width and stud/socket registration. **No surveyed source answers this; that absence is the justification for coupon LG-P2 (clone-plate clutch) and for LG-P1 measuring seam registration on at least one genuine and one clone plate.**

## 3. Prior art: one image/pattern split across multiple LEGO-compatible pieces

- **LEGO Art 31203 World Map** — fetched review at https://www.thebrickfan.com/lego-art-world-map-31203-review/. 40 16×16 baseplates; "The baseplates allow you to connect the panels together by using Technic pins and plates on the back side," reinforced with 2×6 plates on the back — which "don't work that well as they tend to pop off at various locations when you move the map around," and the reviewer wanted six extra vertical plates to stop flex. Registration is therefore *mechanical and positive* (Technic pins between panels), not reliant on a common baseplate underneath — the opposite of our approach — and even so, panel-joint rigidity is the reported weak point. Jay's Brick Blog part 1 (fetched, https://jaysbrickblog.com/reviews/review-lego-31203-world-map-art-part-1/) contains no connection detail. Access failed: https://brickset.com/article/59534/review-31203-world-map (403), https://rebrickable.com/blog/382/review-31203-1-lego-art-world-map/ (403), https://brickarchitect.com/2021/review-31203-lego-art-world-map/ (429). None of the fetched reviews evaluates seam visibility between panels quantitatively.
- **LEGO Mosaic Maker 40179** — product page access failed (https://www.lego.com/en-us/product/mosaic-maker-40179, 403). Search snippets (snippet-only) describe ~4,500 1×1 plates on a single large canvas with a frame; on that description it is single-plate and has no piece-seam problem to solve. Not verified by a fetched page.
- **dlvoy/base-plate-outliner** — fetched https://github.com/dlvoy/base-plate-outliner. PNG (dark = inside) → "optimally decomposes the shape into rectangular baseplates" → OpenSCAD; options include `--border [THICKNESS_MM]` (default 5 mm) and a base height of 3.2 mm (a full plate, not LEGO's 1.6 mm baseplate). **It splits a shape into multiple printable plates but its README says nothing about seams, inter-plate tolerances, or registration validation.**
- **MachineBlocks** — fetched https://machineblocks.com. Web editor generating 3MF/STL LEGO-compatible blocks, "Perfect fit can be achieved with the Calibration Tool" — i.e. it acknowledges per-printer calibration (kin to our LG-P2) but the visible pages document no numeric tolerances and nothing about splitting one pattern across multiple pieces.
- **Christopher Finke, printed LEGO-compatible bricks** — fetched https://www.chrisfinke.com/2015/01/27/3d-printed-lego-compatible-bricks/. Dimensions based on measuring real bricks; a `stud_rescale` parameter exists because stud size must be tuned per printer "to get the studs to print at just the right size"; prior printable brick models "none of them were designed accurately enough to reliably interlock with genuine LEGO bricks"; his own verdict on clutch: "acceptable to my six-year-old son, but not satisfying to me." Direct precedent for making clutch a calibrated, per-printer quantity.
- **Printables/Thingiverse split-pattern search** — searches under several phrasings ("multi plate lego mosaic 3d print", "split image across multiple printed plates", etc.) surfaced: a printable 32×32 baseplate explicitly derived from LDraw 3811.dat (https://www.printables.com/model/330624-lego-compatible-3811dat-baseplate-32-x-32 — **access failed, 403**, so whether it is split for the print bed and how it handles joins is unverified); MachineBlocks STL generators on Thingiverse; whole-brick libraries (PrintableBricks, thing:4787193). **Of the projects surveyed here, none was found that splits one continuous relief/pattern across multiple LEGO-compatible printed pieces and validates seam registration** — the closest items either split blank plates (dlvoy, unvalidated) or tile 1×1 colored studs (mosaic services, where the grid itself is the image and seams carry no pattern continuity). This is a genuine gap; our LG-P1 coupon has no published predecessor in the surveyed set.

## 4. Seam visibility at ~0.2 mm and FDM edge quality

### 4.1 Sourced visual-acuity facts

- **Vernier (alignment) acuity: 2–5 arcsec.** Fetched https://pmc.ncbi.nlm.nih.gov/articles/PMC8523788/ (Hu, Ayton, Jolly, "The Clinical Use of Vernier Acuity…"): "The vernier threshold (smallest detectable offset) for humans is as low as 2 to 5 arcseconds," vs a foveal cone subtending ~30 arcsec; vernier acuity ~10× finer than ordinary acuity. (Attempted primary alternatives failed: scholarpedia.org/article/Hyperacuity — connection refused; the Webvision acuity chapter (fetched via redirect at https://www.webvision.pitt.edu/book/part-viii-psychophysics-of-vision/visual-acuity/) confirms 20/20 = 1 arcmin stroke width and ~60 cycles/deg ceiling but gives no numeric vernier threshold.)
- **Minimum visible dark line: down to ~0.5 arcsec at high luminance** (Hecht & Mintz 1939, "The visibility of single lines at various illuminations…"). **Snippet-only:** the number comes from search-result text around the Semantic Scholar entry (https://www.semanticscholar.org/paper/381605e7e9ce3157aac34b7a4a3e749b2711eb28); I did not fetch the paper itself. Range quoted: ~10 arcmin at lowest illumination down to ~0.5 arcsec at highest.
- **Ordinary resolution acuity: 1 arcmin** stroke width at 20/20 — fetched Webvision chapter (Kalloniatis & Luu), as above.
- **FDM dimensional accuracy.** Fetched https://www.hubs.com/knowledge-base/dimensional-accuracy-3d-printed-parts/: FDM desktop "±0.5% (lower limit: ±0.5 mm)", FDM industrial "±0.15% (lower limit: ±0.2 mm)"; shrinkage 0.2–1% by material. Fetched https://jlc3dp.com/blog/accuracy-prototyping: XY accuracy "±0.1 mm to ±0.3 mm", wall tolerances "±0.2 mm typically", and a recommendation to design FDM tolerances ≥0.2 mm. (These two disagree at the desktop end — Hubs' ±0.5 mm floor is conservative service-bureau language, JLC's ±0.1–0.3 mm matches tuned-printer practice; recorded, not resolved. A well-calibrated modern bedslinger/CoreXY at 0.4 mm nozzle sits at the good end of the JLC range, but that placement is our judgment, not a fetched number.)
- **Elephant's foot.** Fetched https://help.prusa3d.com/article/elephant-foot-compensation_114487: the first layer "is squished against the heated print bed and as a result, it's usually a bit wider than it should be"; PrusaSlicer's compensation default guidance: "Values around 0.2 mm usually work well for the default 0.4 mm nozzle" — i.e. the uncompensated first-layer bulge is itself in the 0.1–0.2 mm-per-side class, the same order as our whole designed seam.

### 4.2 Our inference (clearly separated from the sourced facts above)

Geometry at a 45 cm viewing distance (pure arithmetic, no source needed): 0.2 mm subtends atan(0.2/450) ≈ **1.5 arcmin ≈ 92 arcsec**.

- Against ordinary acuity (1 arcmin) the seam is right at the resolution limit as a *feature*; against minimum-visible dark-line detection (fractions of an arcsec to a few arcsec for high-contrast lines, snippet-sourced Hecht & Mintz) a dark 0.2 mm groove crossing a lit relief will essentially **always be detectable**. Conclusion for the design doc: do not plan for the seam to disappear; plan for it to read as *intentional* — align seams with pattern construction lines of the Islamic geometry so the grid reads as part of the design. (This is our design inference, not a sourced fact.)
- Registration error is the sharper threat than seam existence: vernier acuity of 2–5 arcsec at 45 cm corresponds to a detectable *misalignment* of roughly **4–11 µm** for ideal high-contrast edges. Real FDM edges are rough and low-contrast, so the practical threshold is far coarser — but it is bounded above by FDM XY error itself (±0.1–0.3 mm per JLC, fetched), which means printer error can produce line breaks (a pattern line stepping sideways across a seam) that are one to two orders of magnitude above even conservative alignment-detection thresholds. **A continuous line crossing a seam with a visible lateral jog is the failure mode LG-P1 must measure**, and no tuning of the 0.2 mm gap fixes a lateral jog.
- Elephant's foot narrows the designed gap at the *bottom* layer (0.1–0.2 mm/side bulge could close a 0.2 mm seam to interference and prevent flush seating — a mechanical, not visual, failure). The viewed face is the top; top-surface corner rounding and outer-perimeter bulge at the top edge will *widen and soften* the apparent seam beyond the nominal 0.2 mm. I found no fetched source quantifying top-edge corner rounding at 0.4 mm nozzle; treat "apparent top seam width = 0.2 mm + 2× top-edge rounding" as an unknown for LG-P1 to measure, and print pieces with elephant-foot compensation ≈0.2 mm (Prusa guidance, fetched) so the bottom does not govern fit.

---

**Key takeaways for the design doc and coupons:** (1) The 8.0 mm pitch and the 0.2 mm inter-part gap are solid — LEGO's own bricks carry the identical 0.1 mm/side relief, so the piece footprint rule inherits a proven convention. (2) The baseplate is 1.6 mm (4 LDU) thick, not 8 LDU. (3) Stud diameter/height measured values run 0.05–0.2 mm above LDraw nominals — clutch must be calibrated, not copied (LG-P2). (4) No surveyed prior art both splits one continuous pattern across printed LEGO-compatible pieces *and* validates seams — LG-P1 is genuinely novel ground. (5) The 0.2 mm seam will be visible at viewing distance under any sourced acuity number; the design should make it deliberate, and the coupon should measure lateral line-jog across seams, which FDM XY error (±0.1–0.3 mm) can push orders of magnitude past alignment-detection thresholds.
