**Decision (2026-09-16, Omar):** build a **`print-model` skill** that walks a model to the edge of dispatch, plus a **print-metadata** extension. Scope chosen = **Option A: up to the owner gate, no dispatch port yet** — the skill's deliverable is a reviewable *per-print plan + sliced plate + preview*; dispatch stays the existing gated `bambu print send` (Omar's button). Rejected: porting real dispatch first (it's the CAL-gated hardware verb we can't use yet) and doing both at once.

**North star (Omar's framing):** the skill is a **sage master 3D-printer operator** — you ask it to print something and it makes sure you're not getting in your own way; it prints how a master would. So it is proactively advisory: discovers loaded filament, recommends the **nozzle** (0.2/0.4/0.6/0.8 — X2D ships all four), reasons **orientation** and **supports/infill/brim**, **packs repeats on the grid** and says **when to rotate-to-fit**, offers to **fill unused bed** ("more copies? another piece?") or **scale up**, and **catches footguns** (too-thin wall for the nozzle, needless supports, fragile layer direction, wrong filament) — each a one-line "what a master would do + why", never an auto-change (owner decides). A **best-practices reference** beside SKILL.md (`.claude/skills/print-model/best-practices.md`, read at run time) holds the grounded rules + our real examples, and the skill is **self-healing**: physical-iteration findings graduate new rules/examples into it (mirrors the repo graduation rule). Calibration coupons are the exception everywhere — their settings are *measurements* fixed by the bench sheet, not suggestions.

**Why not just more CLI:** the orchestration (discover AMS filament → AskUserQuestion pick → reason orientation/infill/supports → compose a plan → handle print-issue feedback) is judgement work a skill owns; the CLI keeps the atomic verbs.

**The load-bearing gap under it:** `print send` still imports `McpBackend` (griches MCP, not on npm) — so dispatch would fail at connect *exactly like status did pre-#188*. Real submit = first-party **FTPS 3mf + MQTT `print.project_file`** (what Studio/Handy do). That port is deferred (own owner-gated PR); the skill stops before it. See [[bambu-x2d-bringup]].

**Records are gitignored until shipped:** `.bambu/` is gitignored (drafts local); a record is tracked only when promoted to `docs/prints/<date>-<slug>/`, and must pass the *whole-tree* `prints_gate.py` to commit. That draft→shipped promotion already encodes the ends of the `status` lifecycle Omar wants.
